SYSTEM SPECIFICATION LOCAL-FIRST

Core Architecture Principles

  • 01. Separate Prediction & Training Predictions are suggestions. A newly ingested email never automatically becomes a training label. Only explicit human confirmation writes to the feedback ledger.
  • 02. Immutable Candidate Registry Candidate models are compiled into isolated snapshots. Active predictions never change until a candidate passes evaluation and is explicitly activated.
  • 03. Enforced Evaluation Gates Activation is physically gated by the application service. The UI prevents promoting candidates that have not been scored on held-out evaluation data.
  • 04. 1-Click Rollback Integrity Restoring an earlier model version immediately reverts classification weights, prediction baselines, and confidence states in SQLite.

03CONTINUOUS IMPROVEMENT

The 7-Stage Learning Loop

From ingestion to reversible activation: how InboxLearn improves accuracy safely without catastrophic forgetting or unverified drift.

STAGE 01

Import

Ingest raw email data from CSV, RFC 822 (.eml), or Unix .mbox archives. Content is parsed and stored locally in SQLite without remote leaks.

Multi-Format Intake
STAGE 02

Classify

Stateless HashingVectorizer extracts n-grams. Dual incremental SGD classifiers generate raw category and priority scores.

Dual SGD Models
STAGE 03

Review

Predictions falling below confidence thresholds (0.70) are flagged and automatically routed to the human review desk.

Uncertainty Gate
STAGE 04

Correct

The human operator confirms or alters labels. Corrections are recorded transactionally with full timestamp and revision history.

Human Authority
STAGE 05

Retrain

The system trains an isolated candidate model from baseline seed plus latest corrections. Live predictions remain strictly unchanged.

Candidate Isolation
STAGE 06

Evaluate

Candidate model is scored on a disjoint held-out test split. Confusion matrices and accuracy deltas are presented for inspection.

Held-Out Benchmark
STAGE 07

Roll Back

Promotion is human-approved. If regressions appear later, an instant 1-click rollback restores prior model weights and predictions.

Zero-Risk Safety
Why this architecture matters: Standard auto-learning systems silently poison their own training sets when automated predictions are recycled as ground truth. InboxLearn guarantees that only human-confirmed decisions inform new model weights.

HONEST SPECIFICATION · NO EXAGGERATION

Trust, Safety & Architectural Limitations

InboxLearn prioritizes technical truthfulness over marketing claims. Below is our formal transparency contract.

1. Model Learns Only from Confirmed Feedback

Automatic model predictions are strictly never treated as ground truth labels. The machine learning pipeline only digests rows explicitly confirmed or edited by a human reviewer.

2. Actions Are Suggestions Only

The system suggests follow-up actions and priorities, but executes zero external destructive operations. InboxLearn will never delete emails, send replies, or draft messages autonomously.

3. Confidence Estimates Are Uncalibrated

The displayed confidence percentages represent raw logistic loss scores, not true calibrated probabilities. A 0.85 estimate indicates internal model margin, not an 85% statistical likelihood of correctness.

4. Demonstration Data Uses Synthetic Messages

All benchmark numbers published in portfolio reports reflect the bundled synthetic demo fixtures (15 seed emails, 5 feedback messages, 10 held-out examples). They do not represent real-world corporate accuracy.

5. Gmail & Clerk Auth Are Roadmap Features

Direct live Google Gmail OAuth write connectivity and Clerk user authentication are future roadmap capabilities, currently disabled or planned for multi-user releases. The current system operates strictly locally.

6. No Privacy Claims for Hosted Environments

When executed locally on your machine, data never leaves your computer. However, if deployed to public hosted services (e.g. Streamlit Cloud), privacy depends on the host's infrastructure; no zero-knowledge encryption is claimed.

PORTFOLIO AUDIT STATEMENT: This software is a focused portfolio implementation demonstrating machine learning software engineering, human-in-the-loop lifecycle design, and resilient architecture. We do not publish inflated benchmarks, fake user counts, or claims of total autonomy.
06TECHNICAL DIFFERENTIATION

How InboxLearn Differs

Compare InboxLearn against conventional email management solutions, static rules, and generative AI wrappers.

Dimension InboxLearn (Human-in-the-Loop) Static Rules & Filters Cloud LLM Wrappers
Human Review Integration Native review queue: Uncertain predictions flagged automatically for human confirmation. Manual rule updates required; no uncertainty detection. Black-box outputs without structured confidence thresholds.
Continuous Learning Incremental retrain: Learns from human corrections with candidate snapshot isolation. Static regex/sender matching; cannot adapt to semantic shifts. Prompt engineering only; base weights cannot be updated locally.
Evaluation & Safety Gate Held-out verification: Service blocks candidate activation until tested on fresh data. None; rule syntax errors or broad matches silently misfile emails. Hallucinations cannot be programmatically benchmarked offline.
Rollback Capability Instant 1-click rollback: Reverts weights, predictions, and SQLite state atomically. Manual filter undo; no state history. None; prompt edits often cause unpredictable secondary regressions.
Privacy & Operational Cost Local-first: Runs on CPU via Python/SQLite. Zero token costs, zero API keys. Local email client execution. Transmits full email bodies to cloud LLM APIs; recurring subscription fees.
